# LifeOS V0.1 P0 Requirement Traceability Matrix

> - 文档类型：工程追踪与验收映射
> - 状态：Stage 0 Baseline
> - 产品权威：不高于 Product Constitution、Master PRD、V0.1 PRD、Decision Log 与 `CONTEXT.md`

## 1. 用途与边界

本文件把 V0.1 的 14 项 P0 Requirement 和 22 项 P0 Acceptance Criteria 映射到交付阶段、领域对象、入口、状态/边界、风险和最低验证证据。它帮助工程实现和测试追踪范围，不新增产品行为。

若本文件与产品文档冲突，以产品文档为准并停止相关实现。标记为 `PRODUCT DECISION REQUIRED` 的缺口不能由实现 Agent 在代码中自行补齐。

来源：

- `LifeOS_V0.1_PRD.md` §2.1、§3–§10、§12.1；
- `LifeOS_Product_Constitution.md` 原则 2、3、4、7、8、9、12；
- `LifeOS_Master_PRD_v1.0.md` §4、§5.3、§6、§18.5、§20、§24.1；
- `LifeOS_Decision_Log.md` D-021、D-026、D-031；
- `CONTEXT.md` 的统一领域语言。

## 2. 交付阶段

| Stage | 交付边界 |
|---|---|
| S1 | 私有、本地优先的文字/原始语音 Capture → Now/Today Timeline → 离线重启恢复 |
| S2 | Session 生命周期、Entry、Spark 与现场记录闭环 |
| S3 | Task/DDL、完整 Today Timeline、Unknown 修复、Life Area、Daily Review |
| S4 | 隐私/删除/Settings 完整化，以及经产品决策批准的数据导出边界 |
| S5 | Windows↔Android 安全局域网同步与最小冲突处理 |
| S6 | 跨平台 P0 全量验收、打包、迁移与崩溃恢复加固 |

上述 S1–S6 保留为需求归属和验收包标识，不再要求整个 S1 语音包完成后才能推进 S2/S3 文字能力。当前按[文字优先内部试用路线](./Text_First_Trial_Implementation_Route.md)执行；先回看及本地删除，再推进文字行动与回顾闭环。语音、同步、跨对象删除和完整发布验收继续为未完成项，不能因内部试用而勾选通过。

## 5. Stage 1 可执行验收包

下列验收只定义第一条本地价值切片，不声称完成 V0.1 全部对应 Requirement。

| Stage 1 ID | Testable outcome | Evidence type |
|---|---|---|
| S1-AC-01 | 同一受控源码和领域契约可命令行构建 Windows 与 Android 壳；两端均能启动到 Now/Capture 入口 | Build logs + smoke test |
| S1-AC-02 | 无网络时，不先选内部类型即可保存一句文字 Capture；首次写入默认 Private | Integration + persistence inspection |
| S1-AC-03 | 麦克风权限允许时可录制原始语音，音频先可靠落盘，再建立引用它的 Raw Capture | Device integration + file/database inspection |
| S1-AC-04 | 麦克风拒绝、用户取消或文件保存失败时显示真实状态，不创建“成功” Capture，也不遗留被当作正式记录的半成品 | Permission/fault-injection tests |
| S1-AC-05 | 保存后关闭进程或重启设备，文字原文和原始音频仍可从 Now/Today Timeline 打开，音频可播放 | Restart/recovery E2E |
| S1-AC-06 | 转写、摘要、标题、分类和关联使用独立派生存储；新增、修改或删除派生内容不会改变原文/原音频的内容与校验值 | Repository unit/integration tests |
| S1-AC-07 | Today Timeline 以发生时间展示本地 Capture，并明确其仍为 Raw/未整理状态；不生成 Session、Task、Moment 或 AI 事实 | UI + domain assertions |
| S1-AC-08 | 删除原始语音 Capture 后，原音频不再可用且不会继续被有效索引/派生处理；具体隐藏/归档/跨设备传播 UX 留待后续阶段 | Data lifecycle test |
| S1-AC-09 | 网络、AI 与同步模块完全不可用时，S1-AC-02 至 08 仍可完成 | Offline/fault-injection E2E |
| S1-AC-10 | 从上一测试 schema 升级到下一 schema 后，已有原文、音频引用、来源、时间与隐私值保持不变；失败迁移不得提交半个版本 | Migration + crash-recovery test |

## 6. 明确不在 Stage 1

- Session 生命周期、Session Entry 和 Spark 完整语义（S2）；
- Task/DDL、下一步排序、Unknown 修复、Life Area、Daily Review（S3）；
- 完整 Space/Visibility/私密模式、导出边界和跨对象删除传播（S4）；
- 设备配对、LAN 传输、冲突处理及原始语音文件同步范围（S5）；
- 照片、截图、视频和任何媒体→Session 的结构化关联（P1）；
- AI 整理、外援、云同步、Moment/Echo/Ask My Life 及其他后续能力。

## 8. 机械完整性规则

- Requirement ID 必须恰好覆盖 `V0-P0-01` 至 `V0-P0-14`，不得缺失或重复；
- Acceptance ID 必须恰好覆盖 `AC-P0-01` 至 `AC-P0-22`，不得缺失或重复；
- Stage 1 只能声称 S1 验收和对应的 Requirement 切片，不能把部分覆盖标成完整 V0.1 Pass；
- 新增用户可见行为时，必须先回到产品文档和 Decision Log，不能只更新本矩阵。
