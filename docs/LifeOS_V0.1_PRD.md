## 0. 版本定位

V0.1 不是完整 LifeOS 的缩小愿景，而是对长期主循环的第一段验证：

> **Capture → Session/Task → Timeline → Daily Review**

首版要回答一个问题：

> 用户能否在不被复杂表单打断的情况下，连续使用一段时间，并在晚上清楚看到“今天原来是这样度过的”？

V0.1 不追求把所有未来能力塞进首页，也不因为暂时没有 Echo、关系或完整成长分析就改变 Master PRD 的长期定义。

### 0.1 文字优先内部试用里程碑（D-035）

先交付可实际使用的文字基础闭环，再恢复原始语音实现。内部试用按可靠文字 Capture、回看与本地删除、Session、Entry/Spark、Timeline/Unknown/Daily Review、基础 Task/DDL 分批推进，并依据实际依赖组织验收。目标是可靠和顺手，不是无限打磨文字编辑器。

此安排仅调整实施顺序：下列 P0 范围与完整 V0.1 验收不变，原始语音仍为 P0，转写不是基础流程的前置条件。已验证的存储结构保留；文字试用不等于完整 V0.1 已完成。

## 1. 目标与成功条件

### 1.1 V0.1 目标

1. 用户可以快速留下“我现在开始做什么”；
2. 用户可以在活动中途留下火花或现场条目；
3. 用户可以记录计划任务、截止时间和完成状态；
4. 用户可以在时间线上看到当天实际发生的 Session、Task 和 Capture；
5. 用户可以承认未知空白，不被迫猜测；
6. 用户可以通过每日结算完成轻量回顾；
7. 手机和 Windows 在无服务器条件下可以保留各自本地使用，并在可用时进行局域网同步；
8. AI 不可用时，以上核心流程仍然可用。

### 1.2 首版体验目标

- 开始一个 Session：目标约 3 秒；
- 结束一个 Session：目标约 10 秒，补充信息完全可选；
- 捕获一个 Spark：一句话或一段语音即可；
- 每日结算：目标 2–5 分钟，可跳过；
- 首页不展示超过 3 个“下一步建议”；
- 不以“效率分”“失败”“断签”作为主反馈。

### 1.3 V0.1 的成功信号

首版优先观察：

- 用户是否在一周内多次留下真实 Session；
- 用户是否能够在晚上通过 Timeline 复述今天；
- 用户是否会在活动中途使用 Capture/Spark；
- 用户是否愿意在不完整时直接选择“未知”；
- 用户是否在漏记后愿意回来修补，而不是放弃整个时间线；
- 用户是否认为记录过程比回忆整天更轻松。

这些是体验信号，不合并成用户的人生评分。

## 2. 范围总览

### 2.1 P0：V0.1 必须有

| ID | 能力 | 说明 |
|---|---|---|
| V0-P0-01 | 本地可用 | 无网络也能记录、查看、编辑和完成基础结算 |
| V0-P0-02 | Now 首页 | 当前行动、今日任务、最多三项下一步、不可忘事项 |
| V0-P0-03 | 快速 Session | 开始、暂停、恢复、结束、临时活动、跨设备当前状态 |
| V0-P0-04 | Session Entry | 活动中途写一句话或录入火花 |
| V0-P0-05 | Task/DDL | 创建、完成、推迟、取消、预计耗时、截止时间与提醒 |
| V0-P0-06 | 全局 Capture | 文本、原始语音或快捷输入；原始音频本地保存并可回看，允许先留后整理 |
| V0-P0-07 | Spark | 保存未成形的想法并保留当时上下文 |
| V0-P0-08 | 今日 Timeline | 按时间显示 Session、Task、Capture、未知空白 |
| V0-P0-09 | 时间洞补记 | 回答、修改、合并或保留 Unknown |
| V0-P0-10 | Daily Review | 今日回顾、简单统计、成果、遗留事项、归档视图 |
| V0-P0-11 | 基础 Life Area | 允许少量横向领域，不建立复杂分类树 |
| V0-P0-12 | 原始内容可回看 | AI 或整理不得覆盖原始输入 |
| V0-P0-13 | 基础隐私 | 默认私人、基础私密模式、删除和本地数据控制 |
| V0-P0-14 | Windows↔Android 同步 | 至少支持配对设备在局域网/设备热点中交换变化 |

### 2.2 P1：首版可增强，但不应破坏 P0

| ID | 能力 | 说明 |
|---|---|---|
| V0-P1-01 | 简单 AI 整理 | 将自然语言拆为 Task、Session、Spark 或 Journal 候选 |
| V0-P1-02 | AI 外援 | 生成 Prompt、复制、粘贴结构化结果、校验、预览、确认 |
| V0-P1-03 | Session 轻量总结 | 根据用户补充生成成果/分段草稿 |
| V0-P1-04 | 协会建议 | 根据 DDL、未完成任务和近期节奏推荐最多三项下一步 |
| V0-P1-05 | 任务拆分建议 | 对过大任务建议拆成更小步骤，但不直接改写 |
| V0-P1-06 | 简单媒体关联 | 用户主动将照片、截图、视频或已有原始语音等媒体结构化关联到 Session；不包含 P0 的原始语音 Capture 保存能力 |
| V0-P1-07 | 周视图 | 展示本周生活节奏和任务推进，不做深度变化分析 |
| V0-P1-08 | 数据导出/备份 | 让用户能带走本地人生记录，具体格式另定 |
| V0-P1-09 | 设备冲突审阅 | 展示重叠或不同修改，允许用户决定 |

### 2.3 P2：明确后置

以下属于 Master PRD 的长期能力，但不应成为 V0.1 的前置条件：

- 自动观察应用、位置、设备状态并生成 Evidence；
- 完整游戏截图识别、赛季数据、六维图和风格分析；
- 完整 Goal/Direction/Project/Milestone/Chapter 体系；
- People、关系 Era、地点档案和共同时间线；
- Moment 候选、Echo、时间胶囊和长期回响调度；
- Ask My Life 多年档案研究；
- 完整 Yearly/Chapter Review、Then & Now；
- 完整 RPG 职业、装备、收藏、人生博物馆；
- 云同步、对象存储和多备份位置；
- 蓝牙同步；
- 微信/飞书深度监控或自动导入；
- 好友可浏览的社交网络式主页；
- 医疗或心理诊断能力。

## 3. V0.1 信息架构

V0.1 不强行上线空壳的完整四大模块，而采用以下可用入口；长期的 Journey 与 Archive 在数据语义上预留，但不以空页面制造导航负担。

### 3.1 Now / 现在

默认首页，回答：

1. 我现在在做什么？
2. 接下来可以做什么？
3. 今天有什么不能忘？

主要区域：

- 当前 Session 卡片；
- `+ Capture` 和 `▶ 开始做一件事`；
- 今日必须处理/Commitment；
- 最多三项下一步建议；
- 今日已发生的时间线缩略；
- “结束今天/今日结算”入口。

### 3.2 Timeline / 时间线

默认定位到今天，支持选择日期和查看：

- Session 大节点；
- Session 内 Entry；
- Task 创建、完成和推迟事件；
- Spark/Capture；
- 未知时间洞；
- 简单 Life Area 统计；
- “这段时间发生了什么？”的展开视图。

### 3.3 Tasks / 任务

V0.1 的任务池单独可访问，但不能占据 Now 的全部空间。支持：

- 今天；
- 即将到期；
- 已推迟；
- 无日期；
- 已完成/已取消。

未来 Goal/Project 可在任务上保留可选关联字段，但不要求 V0.1 建立完整目标树。

### 3.4 Capture / 全局捕获

从任何页面打开的快速入口。默认光标在输入区，不要求先选类型。

可选动作：

- 写一句话；
- 录一段原始语音（P0，原始音频本地保存）；
- 添加图片、截图或视频并进行结构化媒体关联（P1）；
- 开始 Session；
- 结束/补记 Session；
- 保存 Spark；
- Brain Dump。

### 3.5 Daily Review / 今日结算

从 Now 或 Timeline 打开。它不是问卷，而是修复今天、看见今天、结束今天的轻量流程。

### 3.6 Settings / 设置

首版至少包含：

- 默认隐私与私密模式；
- 设备配对与同步状态；
- AI 处理开关/来源说明；
- 通知和提醒强度；
- 数据导出、删除和清理；
- 时间、时区和日界线设置。

## 4. 页面与交互需求

### 4.1 首次使用与最小设置

#### 目标

让用户尽快开始记录，不让 onboarding 变成“先规划人生”。

#### 必须

- 说明 LifeOS 默认私有、本地优先、AI 可选；
- 设置显示名称或昵称（可跳过）；
- 确认时区和一天的开始/结束边界；
- 允许用户直接创建第一项任务，也允许直接开始第一个 Session；
- 不要求填写人生愿景、职业规划、完整分类或十年目标；
- 说明“未知空白”和“稍后整理”是合法状态。

#### 首次成功路径

```text
打开 LifeOS
  ↓
看到隐私与离线说明
  ↓
选择“开始一件事”或“先记一个想法”
  ↓
完成第一次 Capture/Session
  ↓
回到 Now
```

### 4.2 Now 页面

#### 当前无 Session

显示：

> 当前没有进行中的行动

主按钮：

- `▶ 开始做一件事`；
- `💡 记一个火花`；
- `＋ 随手记`。

辅助区域：

- 最近使用的活动快捷项；
- 今日必须处理的 Commitment/Deadline；
- 最多三项推荐 Quest；
- 今日已记录时长与最近一条时间线。

#### 当前有 Session

显示：

- Session 名称；
- 已持续时间；
- 开始时间；
- 关联 Task（如有）；
- `＋ 发生了什么`；
- `💡 保存火花`；
- `暂停`、`结束`、`切换活动`。

不在首屏显示复杂统计，不要求用户实时填写阶段、情绪或结果。

### 4.3 开始 Session

入口可以是 Now、任务、最近项、快捷键或全局 Capture。

输入方式按负担从低到高：

1. 点最近活动；
2. 输入一句自然语言；
3. 语音描述；
4. 选择可选 Life Area 或关联 Task。

如果用户只输入“开始”，系统应允许先创建“未命名行动/待补充”，之后再改名。

确认前显示：

- 名称；
- 可选关联任务；
- 可选主要领域；
- 是否作为主活动。

开始后立即进入计时，不等待 AI 或网络。

### 4.4 Session 进行中

#### P0 必须支持

- 看到持续时间；
- 一键添加 Entry；
- 一键捕获 Spark；
- 暂停/恢复；
- 结束；
- 切换主活动或记录插曲；
- 在设备切换后继续看到同一 Session。

#### 启用 P1 媒体关联后

- 用户可以一键选择媒体，并将其结构化关联到当前 Session。

#### Entry 输入

默认是一个轻量输入框，例如：

> 今天副歌第一次完整弹下来了

旁边可以有火花入口。P0 也可以从这里打开独立的原始语音 Capture；该入口只保存 Raw Capture，不因入口位置自动成为 Entry 或关联当前 Session。若录音、照片或其他媒体要作为 Entry 关联当前 Session，则属于 P1。保存后不强制要求分类或总结。

#### 插曲与切换

- 短暂行为可作为当前 Session 的插曲；
- 明显不同且持续较久的行为可以切换为新主 Session；
- 用户之后可以合并或拆开；
- 不要求每次切换都弹窗打断。

### 4.5 结束 Session

第一屏只显示事实：

- 实际开始时间；
- 实际结束时间；
- 实际持续时长。

可选问题最多一个：

> 这段时间主要做了什么，或者有什么结果？

P0 用户可以：

- 输入一句；
- 打开独立的原始语音 Capture；该录音只保存为 Raw Capture，不自动成为 Outcome 或关联当前 Session；
- 直接跳过。

启用 P1 媒体关联后，用户还可以把录音、照片或其他媒体作为 Entry/Outcome 结构化关联到当前 Session。

如果启用 AI，AI 只能生成成果/分段/标签草稿；用户未确认前不视为正式事实。

### 4.6 Task/DDL 页面

#### 创建

最小字段：

- 标题；
- 是否有 Deadline；
- 可选预计耗时；
- 可选提醒；
- 可选 Commitment 标记；
- 可选备注/来源。

#### 操作

- 完成；
- 推迟；
- 取消；
- 拆分建议；
- 修改 DDL；
- 开始一个关联 Session；
- 查看相关 Session 和 Capture。

#### 任务体验

- 普通 Task 与 Commitment/Deadline 视觉上区分；
- 任务错过不显示“惩罚”；
- 预计耗时只是帮助排期，不是用户承诺；
- 大任务可以提示“这可能更适合成为 Project”，但 V0.1 不强迫建立 Project；
- 多次推迟后可以温和询问原因，支持“其实不重要/太大/不知道怎么开始/时间不够/不想做了/其他”；
- 用户可以选择“今天不处理”，不会被系统继续升级骚扰。

### 4.7 Global Capture 与 Inbox

#### 输入原则

- 默认先保存，再理解；
- 不先要求选类型；
- 一句话可以包含多个内容；
- 用户可以选择“稍后整理”；
- 原始内容始终可回看。

#### P0 原始语音边界

- 原始语音是 P0 的一等 Capture 输入，不依赖 AI、网络或转写成功；
- 录音完成后先将原始音频可靠保存在本地，用户之后仍可播放和删除；
- 原始语音 Capture 的时间采用开始录音时间（D-032），保存完成时间仅作存储提交信息；跨日录音按开始时刻展示，保存重试不得改写该时间；
- 用户录音时切换到其他应用、LifeOS 进入后台，应停止本次录音并本地保留音频；用户回来后选择保存或丢弃（D-033）。待决定音频不是已保存 Capture，不进入 Timeline/统计；重启清理不得把它当作无引用垃圾删除，不自动保存、续录或过期删除；无法确认停止或文件完整时必须真实呈现失败/不确定状态；
- 转写、摘要、标题、分类和 Session 关联都属于派生内容或建议，不能替换原始音频；
- 麦克风权限被拒绝、录音取消或保存失败时，应显示可理解的状态，不创建伪造的成功 Capture；
- 照片、截图、视频以及媒体与 Session 的结构化关联属于 P1，不作为 P0 核心闭环前置条件；
- 原始语音文件是否进入 P0 局域网同步范围，留待同步阶段按 D-021 和 D-031 单独确认；当前决定只要求每台来源设备本地可保存、回放和删除。

#### 建议结果

系统可以提出：

- 这是一个 Task；
- 这是一个 Spark；
- 这是对当前 Session 的 Entry；
- 这是一个 Journal/自我观察；
- 这是一个未知时间段的补记；
- 这是一个媒体证据。

当无法确定时，保留 Raw Capture，不强行分类。

#### Inbox 列表

只突出需要用户决定的项目：

- 待确认；
- 待整理；
- 待识别；
- 待归属；
- 待高级 AI；
- 原始保留。

用户可以全部处理、批量处理、稍后处理或永久保留原始状态。

### 4.8 Timeline 页面

#### 日视图

每个 Session 作为大卡片，Entry 作为内部节点。例如：

```text
09:10–10:42  工作
              09:53  💡 一个火花
              10:21  完成一项子任务
10:42–11:03  休息
11:03–11:37  吉他
11:37–12:14  未知空白
```

#### 操作

- 点开查看原始 Capture、结果和媒体；
- 修改时间；
- 添加 Entry；
- 关联 Task；
- 标记为未知；
- 合并或拆分；
- 从一段空白开始补记；
- 查看当天基础统计。

#### 事实分层

至少用清晰但不吓人的视觉方式区分：

- 用户确认的记录；
- 原始未整理内容；
- 自动/AI 候选（如 P1 开启）；
- Unknown。

### 4.9 Daily Review 页面

#### 顺序

1. 看今天已记录的时间线；
2. 选择是否处理时间洞；
3. 选择是否处理少量 Inbox；
4. 回答“今天做成了什么”；
5. 回答“有没有值得留下的时刻”；
6. 选择带到明天的事项；
7. 生成今日可编辑视图。

所有步骤可跳过。当天“归档”只是完成一次回顾，不是锁死数据。

#### 输出

示例：

> 2026-08-29
>
> 已确认记录：工作 4h12m、游戏 2h18m、吉他 38m、社交 1h05m
>
> 还有 1h06m 不确定
>
> 今日完成：4 项任务
>
> 今日留下：2 条火花、1 条现场记录
>
> 明天带入：工作材料、吉他 15 分钟

不显示“今天效率 72 分”，也不把游戏/休息默认标为负面。

### 4.10 基础统计

V0.1 只提供描述事实的统计：

- 各 Life Area 时长；
- 已记录与 Unknown 时长；
- Task 完成/未完成数量；
- Session 数量和总时长；
- Spark/Capture 数量；
- 本周出现频率。

不得输出人生总分、人格评分或道德评价。

## 5. 状态模型

### 5.1 Capture/Inbox 状态

| 状态 | 含义 | 用户动作 |
|---|---|---|
| Captured | 原始内容已保存 | 继续生活、稍后处理 |
| Drafted | 已形成结构化草稿 | 审阅、修改、保留原文 |
| Needs Review | 有候选结果等待确认 | 接受、修改、拒绝 |
| Enriched | 已有 AI/用户补充信息 | 查看来源、继续补充 |
| Archived Raw | 用户选择只保留原始内容 | 随时打开或重新整理 |
| Deleted | 用户明确删除 | 不再进入有效统计/AI |

### 5.2 Session 状态

| 状态 | 进入条件 | 允许操作 |
|---|---|---|
| Planned | 从 Task 或建议准备开始 | 开始、修改、取消 |
| Active | 用户确认开始 | Entry、暂停、切换、结束 |
| Paused | 用户主动暂停 | 恢复、结束、修改暂停区间 |
| Completed | 用户结束或补齐结束时间 | 补充结果、关联、合并、拆分 |
| Needs Repair | 忘记结束、时间冲突或跨设备冲突 | 修时间、合并、保留 Unknown |
| Archived | 用户归档历史 | 查看、恢复、删除 |

### 5.3 Task 状态

| 状态 | 语义 |
|---|---|
| Planned | 已计划但尚未开始 |
| In Progress | 有关联 Session 正在推进 |
| Completed | 用户明确完成 |
| Deferred | 用户选择之后再做 |
| Overdue | Deadline 已过但未完成 |
| Cancelled | 用户取消，不再继续 |
| Archived | 离开当前任务列表但保留历史 |

### 5.4 同步状态

| 状态 | 用户看到的含义 |
|---|---|
| Local Only | 只存在当前设备，仍然可用 |
| Pairing Required | 需要用户确认另一台设备 |
| Syncing | 正在交换变化 |
| Synced | 当前已知变化已交换 |
| Conflict | 存在需要用户决定的差异 |
| Paused | 用户暂停同步 |
| Failed | 同步失败，记录仍留在本地 |

### 5.5 AI 交换状态（P1）

```text
Not Requested
  ↓
Prompt Ready
  ↓
Copied / Sent
  ↓
Imported
  ↓
Validated
  ↓
Previewing Suggestions
  ↓
User Accepted / Partially Accepted / Rejected
```

任何格式错误、来源 ID 不存在或涉及受限数据，都停在审阅阶段，不直接入库。

## 6. 关键用户流程

### 6.1 早上查看今天有什么

```text
打开 Now
  ↓
看当前是否有进行中 Session
  ↓
看今天的 Commitment/Deadline
  ↓
看最多三项下一步建议
  ↓
开始一件事，或只 Capture 一个想法
```

不强制晨间规划，不强制选择人生目标。

### 6.2 开始工作并中途产生火花

```text
点击最近活动“工作”
  ↓
Session Active
  ↓
点击“保存火花”
  ↓
输入想法
  ↓
保存 Raw Capture
  ↓
回到当前工作 Session
```

火花的保存不能结束或暂停当前 Session。

### 6.3 无计划的社交活动

```text
打开快速 Capture
  ↓
输入“和朋友出去吃饭”
  ↓
直接开始临时 Session
  ↓
结束时输入一句结果或跳过
  ↓
晚上再补充人物/主题（可选）
```

不要求先创建 Task、Person 或 Project。

### 6.4 忘记结束 Session

```text
用户第二天发现 Session 仍在进行
  ↓
系统显示“可能忘记结束”
  ↓
建议查看设备/手动记录的时间边界
  ↓
用户选择结束时间、继续、保留 Unknown 或取消
  ↓
保留修正前后的可追溯状态
```

首版即使没有自动证据，也必须允许用户手动修复。

### 6.5 晚上觉得“今天什么都没做”

```text
打开 Daily Review
  ↓
看到已确认 Session、任务和空白
  ↓
选择“未知”或补记少量时间
  ↓
看到中性事实回放
  ↓
选择一项明天可做的小步骤（可跳过）
  ↓
结束今天
```

系统可以说“今天娱乐时间高于近期平均”，但不得说“你今天很差”。

### 6.6 AI 外援整理（P1）

```text
打开 Inbox
  ↓
选择若干待整理 Capture
  ↓
查看本次上下文与隐私范围
  ↓
生成可复制 Prompt/LXF
  ↓
用户交给外部 AI
  ↓
粘贴返回内容
  ↓
校验来源和格式
  ↓
预览建议变更
  ↓
用户逐项或批量确认
```

未经确认的 AI 结果只属于建议，不改变时间线事实。

### 6.7 局域网同步

```text
设备 A 与设备 B 进入同一局域网/热点
  ↓
用户确认已配对设备
  ↓
交换本地变化
  ↓
显示新增、修改、媒体和冲突数量
  ↓
无冲突则完成；有冲突则进入审阅
```

同步失败时两台设备仍可独立使用。

## 7. 异常与边界情况

### 7.1 无网络

- 可以创建、完成和推迟 Task；
- 可以开始/结束 Session；
- 可以保存文字和原始语音 Capture；若启用 P1 媒体能力，照片、截图和视频也必须支持离线保存；
- 可以查看 Timeline 和 Daily Review；
- AI 任务进入待处理；
- 同步状态显示 Local Only，不阻塞用户。

### 7.2 App 被关闭或设备重启

- 已保存的开始时间不能丢失；
- Active Session 恢复时显示“仍在进行/可能需要修复”；
- 不因为后台被系统挂起就伪造结束时间；
- 用户可以重新打开并决定继续、结束或修复。

### 7.3 重复点击开始/结束

- 相同操作应幂等或提示当前状态；
- 不创建大量重复 Session；
- 如果用户确实要开始第二个活动，应明确提供“切换/新建”。

### 7.4 跨午夜

- Session 可以跨越午夜；
- Timeline 按实际发生时间分布，但可以提供跨日连续视图；
- Daily Review 不应悄悄截断实际时长；
- 用户可选择将其视为一个连续行动或分成两天。

### 7.5 时间和时区变化

- 旅行或系统时区变化不应修改原始发生时间的事实；
- 用户可查看本地显示时间与记录时区；
- DDL 的时区应明确，不能因设备变化静默提前/延后。

### 7.6 时间重叠

- 允许存在重叠，现实中可能同时通勤和听播客；
- 不能静默覆盖；
- 提示用户选择主活动、次活动、插曲、合并、修改或保留两项；
- 基础时长统计要避免让用户误以为重叠时长等于现实经过时长。

### 7.7 用户不想补记

提供明确的：

- `保留未知`；
- `跳过今天`；
- `以后再说`。

不能把跳过变成红色警告或未完成任务。

### 7.8 AI 不可用或返回坏格式

- 原始 Capture 已保存；
- 显示“稍后处理/改用外援”；
- 不导入半截结果；
- 解析失败时保留原始返回内容供用户复制或放弃；
- 不重复向用户要求同一份原始输入。

### 7.9 同步冲突

以下情况要进入审阅：

- 两台设备同时修改同一 Task；
- 两台设备产生重叠 Session；
- 同一 Capture 出现两个整理结果；
- 一台设备删除而另一台设备修改；
- 媒体已在一端删除但另一端仍有引用。

默认保留信息，不以“最后同步设备”静默覆盖。

### 7.10 媒体不可用

- 记录仍可以保留媒体名称、时间和关联；
- 文件暂时找不到时标记待修复，不删除整条 Record；
- 用户可以只保留文本/转写并移除原文件；
- 私密媒体不会因为普通同步或 AI 失败自动外传。

### 7.11 用户长期离开

- 不弹“落后多少天”；
- 不要求补齐空白；
- 回来时首页只关注今天；
- 可以选择查看离开前的最后一条记录，但不强制回顾。

### 7.12 删除

- 删除前说明是隐藏、移除附件还是彻底删除；
- 彻底删除不得继续出现在统计、AI、搜索或回顾中；
- 删除原始内容后，相关草稿和 Insight 需要失效或标记证据缺失；
- V0.1 至少提供可理解的本地删除语义，不做“表面删掉、后台仍使用”。

## 8. 隐私与权限需求

### 8.1 默认值

- 新记录默认私人；
- 外部 AI 默认不读取 Private/Work 内容；
- 同步默认只在用户配对设备之间进行；
- 位置、应用使用和通讯内容不是 V0.1 默认采集项；
- 任何分享能力都必须是用户主动选择。

### 8.2 V0.1 隐私模式

至少提供：

- `普通个人记录`；
- `私密记录`；
- `暂不观察/暂停 AI`（即使自动观察尚未上线，也为未来语义保留）；
- `仅本地保存`；
- `删除本地数据`。

V0.1 不要求用户对每条记录填写复杂权限，但应允许在 Capture 或设置中改变默认空间。

### 8.3 AI 预览

P1 AI 外援/云 AI 前至少显示：

- 本次将发送哪些 Record/Capture；
- 是否包含原始媒体、日记、工作或关系内容；
- 使用本地设备、配对电脑还是外部服务；
- 结果是建议还是事实；
- 用户可取消。

---

## 9. 同步与数据连续性需求

### 9.1 产品行为

- 每台设备单独可用；
- 同步交换变化，不以一台设备覆盖另一台设备全部资料；
- 当前 Session 在设备间表现为同一个用户行动；
- 重要记录和原始内容应保留来源设备信息；
- 用户能看见同步进度、最后同步时间和失败原因；
- 同步不应阻塞 Capture。

### 9.2 V0.1 同步最小范围

优先同步：

- Task、Deadline、提醒和状态；
- Session 开始/暂停/结束与基本字段；
- Session Entry；
- Spark/Capture 文本和原始语音的记录元信息；
- Daily Review 状态；
- 基础媒体元信息和用户主动选择的媒体（如 P1）。

如果大媒体同步暂时不稳定，可以先同步引用和状态，并明确告知用户文件尚未复制。
原始语音文件本身是否必须进入 P0 同步，属于 D-021、D-031 下的同步媒体范围待决项；在决定前不得假装已同步，也不得删除来源设备上的原始音频。

### 9.3 云服务

云同步不属于 V0.1 的核心依赖。若提供实验入口，必须仍然：

- 明确可选；
- 不改变本地可用性；
- 显示备份与同步范围；
- 支持用户停止使用或导出。

## 10. AI 需求（P1 为主）

### 10.1 适合首版的任务

- 将“明天下午三点交报告”识别为 Task + Deadline 候选；
- 将“开始练琴”识别为 Session 名称；
- 将 Brain Dump 拆成少量 Task/Spark/Journal 候选；
- 将 Session 结束的一句话整理为草稿；
- 根据 DDL 和未完成事项推荐下一步；
- 生成当日摘要草稿。

### 10.2 不适合首版自动化的任务

- 擅自分析人格或心理健康；
- 自动判定用户和某人的关系；
- 自动把应用使用等同于正式 Session；
- 自动生成“人生变化”结论；
- 自动修改时间、时长、DDL 或原始数值；
- 自动发送 Private/Work 内容到外部服务。

### 10.3 AI 外援的最小产品契约

外援结果必须至少能说明：

- 请求用途；
- 选用了哪些来源 ID；
- 返回了哪些建议；
- 哪些是事实、哪些是推断；
- 哪些字段需要用户确认。

LXF 的完整字段不是 V0.1 的数据库设计任务，但产品体验必须坚持“生成 → 粘贴 → 校验 → 预览 → 确认”。

## 11. 事件与文案边界

### 11.1 推荐表达

- “这段时间还没有记录，要补记吗？”
- “你可以保留未知。”
- “这项任务已经推迟多次，要不要看看原因？”
- “今天娱乐时间比最近平均多，但今天仍然发生了这些事。”
- “这是一条 AI 整理建议，原始内容仍在。”
- “今天结束了，之后仍然可以修改。”

### 11.2 禁止表达

- “你今天失败了。”
- “你浪费了 X 小时人生。”
- “连续签到中断。”
- “你应该成为更好的人。”
- “根据这条记录，你和某人的关系已经结束。”
- “AI 已替你完成整理”但实际没有展示来源或确认。

### 11.3 协会接待员

V0.1 可以只作为文案语气存在，不必做复杂 NPC 系统。它的语气应：

- 克制；
- 具体；
- 给选项；
- 支持“今天算了”；
- 不重复骚扰；
- 不把建议包装成命令。

## 12. V0.1 产品验收标准

### 12.1 P0 核心验收

1. 用户在无网络时可以创建并完成 Task；
2. 用户在无网络时可以开始、暂停、恢复和结束 Session；
3. 用户可以开始不属于任何 Task 的临时 Session；
4. Session 的实际开始/结束时间可被用户查看和修正；
5. 用户可以在 Session 内保存 Entry 或 Spark，且不会结束当前 Session；
6. 用户可以用一句文字或一段原始语音创建 Capture，不先选择类型；
7. 原始 Capture 在后续整理后仍可回看；语音 Capture 的原始音频仍可播放，转写或摘要不得替换它；
8. 用户可以选择保留 Unknown，不被强迫猜测；
9. Timeline 能按时间显示 Session、Entry、Task 和 Unknown；
10. Task 与 Session 可以关联，但互不替代；
11. Task 支持完成、推迟、取消和 Deadline；
12. Deadline 过期不会触发经验扣除、红色失败或羞辱文案；
13. Now 页面最多呈现三项下一步建议；
14. Daily Review 可跳过，且跳过不破坏数据；
15. Daily Review 能显示事实统计和未知空白；
16. 用户离开一段时间后重新打开，能从今天继续；
17. 默认新记录是私人；
18. 用户可以删除记录并使其不再参与有效统计；
19. 两台已配对设备可以在局域网中交换至少一组 Task/Session/Capture 变化；
20. 同步冲突不会静默覆盖双方变化；
21. 同步失败不阻塞任一设备本地记录；
22. AI 不可用时，P0 全流程仍可完成。

### 12.2 P1 验收

1. AI 整理失败时原始内容不丢失；
2. AI 建议在用户确认前不修改正式记录；
3. AI 外援 Prompt 显示上下文和隐私范围；
4. 粘贴回来的结构化结果会校验来源 ID；
5. AI 不得修改用户明确记录的时间、时长和原始数值；
6. 协会建议可以被拒绝、替换或暂不处理；
7. 用户主动添加的照片、截图、视频或其他媒体可以通过结构化关联回到对应 Session；
8. 周视图只做事实回顾，不冒充多年变化结论。

### 12.3 长期兼容验收

即使 V0.1 暂不展示以下页面，也不得用错误语义阻断未来：

- Moment/Memory/Echo；
- Goal/Project/Chapter；
- Person/Place；
- Evidence/Insight；
- Ask My Life；
- Cloud Sync 与 AI 外援。

首版可以少做页面，但不能把 Spark 当普通 Task、把 Session 当 Task、把 AI 推测当 Fact，或把未知空白当失败。

---

## 13. V0.1 明确不做的事

为了保护首版连续性，以下内容不进入 V0.1 的 P0：

- 完整 RPG 数值、职业、装备和排行榜；
- 自动扣分、连续签到和惩罚系统；
- 自动读取微信、飞书、全部相册、精确位置或所有应用活动；
- 自动将设备观察写成正式人生事实；
- 多年人格变化和心理状态判断；
- 好友直接浏览 Timeline；
- 复杂关系评分；
- 蓝牙同步；
- 云服务作为运行前提；
- 让用户先填写完整人生规划才能开始使用。

## 14. 从 V0.1 进入下一版的判断

只有当核心日常流程稳定后，才评估增加下一层能力。重点不是“功能是否做得多”，而是：

- 用户是否愿意在活动中途快速 Capture；
- 时间线是否比单纯 Todo 更有价值；
- 用户是否能接受 Unknown 和稍后整理；
- AI 建议是否真的减少了整理负担；
- 同步是否让用户更愿意在手机和 Windows 间切换；
- 哪些记录已经自然产生 Moment、Goal、Person 或 Place 的需要。

下一版本的新增需求必须回到 Master PRD 和 Decision Log，不能因为 V0.1 的页面暂时简单，就把 LifeOS 永久收缩成 Todo + Timer。
